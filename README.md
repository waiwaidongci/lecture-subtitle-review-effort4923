# 讲座字幕审校工时估算

用已完工讲座验证估算口径，为待审字幕预留人手。

青阶讲堂媒制组，四名字幕审校员每周处理校内公开课和行业讲座。 媒制组从转写系统导出视频时长、低置信片段占比、发言切换与待核术语数，再合并审校员记录的实际净工时。排班员把已完工讲座与待审工单放在同一份 CSV，按日期回测特征和惩罚力度，最后把预计分钟数与需人工核排的工单交给值班组长。

- 按视频长短分工容易低估术语密集和多人问答的讲座。
- 同一批工单既用于调参又用于验收时，排班员看不到模型在较新讲座上的误差。
- 超出历史样本范围的待审工单，需要在排班表里明确标出。

## 业务模块

| 模块 | 用途 |
|---|---|
| 字幕排班台 | 查阅业务口径、当班流程及最新运行。主管可以核对审计记录。 |
| 讲座工单 | 下载「青阶讲堂字幕工时_20261110.csv」并核对字段。分析员可导入 UTF-8 CSV，保留数据指纹和原始行。整包工单填写包号与整包实耗，单笔实耗留空。 |
| 整包与更正 | 查看共享工单的归组结果、整包实耗来源与未纳入回测的包；以追加记录更正整包实耗，并发更正全部保留。 |
| 日期切分与选模 | 选择批次和参数并提交后台计算，可从运行列表追踪状态与失效标记。 |
| 估算误差与队列 | 查看业务指标、待审估算、未纳入的包及原因、证据表和解释，通过来源链接回查数据。 |
| 排班复核 | 查看待处理或已完成记录。复核主管可提交排班处置及依据；失效结果须重算后再复核。 |
| 工时清单导出 | 按批查找结果，核对复核状态并下载相应的 CSV。 |

## 演示流程

1. 11 月 10 日 09:00，合并 10 月 26 日至 11 月 9 日的 30 条已完工讲座和 4 条待审工单，其中包含整包 PKG-07、共享工单合并组 PKG-12／PKG-13 与跨分界的 PKG-18。
2. 在「讲座工单」导入「青阶讲堂字幕工时_20261110.csv」，待审工单的实耗分钟留空；整包行只填包号与整包实耗，不填单笔实耗。
3. 打开「整包与更正」核对归组与实耗来源，可对 PKG-07 提交一笔更正并观察追加留痕；并发提交的更正都会保留。
4. 在「日期切分与选模」沿用自动切分或指定 11 月 4 日开始选型、11 月 7 日开始留出。
5. 以 1 为惩罚中心运行，在「估算误差与队列」比较三个特征组与三个惩罚值的选型误差，并查看「未纳入回测的包」中 PKG-18 的分界原因。
6. 查看 11 月 7 至 9 日的留出误差和时长、转写、术语系数，核对待审工单 QJ-N04 的标记。
7. 在「排班复核」记录需人工核排的标记原因，然后从「工时清单导出」下载 CSV 给值班组长。新增更正后旧运行出现「已失效」标记，需重新运行才能复核。

## 计算口径

- 只有已填实耗分钟的工单参与回测。按工单日期从旧到新分训练、选型和留出三段，同日工单始终在同一段。自动切分以有实耗的日期数按约 60%／20%／20% 分段。
- 一起审完的讲座按整包记录：CSV 的 `package_id` 给出包号、`package_actual_minutes` 给出整包总分钟，系统不会把整包实耗摊填到单笔工单。每个包以成员工单各特征之和构成一条观测，目标为整包实耗；未填包号的工单仍是单条观测。
- 共享工单号的包按传递关系自动并为一组。组成员工单日期跨越训练／选型或选型／留出分界时，整组不纳入回测，结果页「未纳入回测的包」逐组列明原因；整包实耗声明冲突的组同样排除，须先提交更正。
- 整包实耗以追加式更正修订：并发提交的两笔更正都保留在更正记录中，重新归组后的计算默认采用时间最新的一笔。
- 每次运行保存数据指纹（批次校验和加全部更正）。重新导入变化的源数据或新增更正都会改变当前指纹，旧运行在列表和结果页标记为「已失效」，且不能提交复核，须重新运行；重算时一律重新归组。
- 三个特征组分别使用视频时长、时长加转写质量、时长加转写质量和术语数。每组比较惩罚中心的 0.1、1、10 倍。
- 用拟合窗口的均值及总体标准差标准化特征。恒定列按零处理。岭回归最小化残差平方和加 λ 乘标准化系数平方和，截距为拟合窗口平均实耗。
- 用选型集 MAE 选参数，依次以 RMSE、较少特征和较强惩罚打破并列。选出后用训练与选型合并重拟合，留出再计算 MAE、RMSE、平均偏差和常数基线 MAE。
- 估算值最低为零，负预测、超出拟合特征范围、工单日期早于或等于最后已完工日期、达到工时阈值均会在队列标记。标准化系数表示其他特征相同时增加一个标准差关联的工时变化。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | MySQL 8 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
